# 异常检测

把门店日经营指标里的**统计异常**挑出来，按严重度排序，给出可执行的排查方向。

**这个技能的价值是"少误报"**：餐饮/零售的周末效应本身就有 30%+ 的正常波动，不做星期对齐、
不拦促销日和小样本，报出来的东西店主看一眼就不信了。四条规则 + 五条假阳性拦截是本技能的骨架。

## 能力描述

四条量化规则逐条扫描，输出**可核对的异常预警清单**：

1. **R1 绝对阈值** —— 营收环比 ≤ -20%、转化率 < 1.5%、退款率 > 5%
2. **R2 离群** —— `|x-μ| > 2σ`；样本 < 14 天时自动回退 IQR(1.5)，因标准差在小样本上不稳定
3. **R3 连续趋势** —— 连续 ≥ 3 天同向且累计幅度 > 10%，单日波动不算趋势
4. **R4 季节性** —— 有去年同期用同比；**同比与环比冲突时以同比为准**并标注冲突

假阳性拦截：促销日 / 节假日 / 新店未满 30 天 → 不判异常；单日订单 < 20 单 → 转化率与退款率
只报值不下结论；区间内缺失日期 → 不补零、环比在缺口处断开。

派生指标（客单价 = 营收 ÷ 订单、转化率 = 订单 ÷ 访客、退款率 = 退款额 ÷ 营收）**由脚本计算**。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `store_name` | string | ✅ | 门店名称，用于标题与产物 |
| `metrics` | array | ✅ | 日指标数组，每行含 `date` / `revenue` / `orders` / `visitors` / `refunds`，可选 `last_year_revenue` |
| `category` | string | ⬜ | `餐饮` / `零售` / `通用`，决定行业基准；缺省 `通用` |
| `period` | object | ⬜ | `{"start":"YYYY-MM-DD","end":"YYYY-MM-DD"}`，用于缺失日期检测 |
| `opened_date` | string | ⬜ | 开业日期，用于新店 30 天保护期判定 |
| `promo_days` | array | ⬜ | 促销日列表，命中则拦截不判异常 |
| `holidays` | array | ⬜ | 节假日列表，命中则拦截不判异常 |
| `rules` | object | ⬜ | 覆盖默认阈值（见 `schema.json`） |

**不要让用户提供客单价 / 转化率 / 退款率** —— 这三个值由脚本从原始字段重算，用户给了也以脚本为准。

## 输出规格

| 字段 | 类型 | 说明 |
|------|------|------|
| `summary` | object | 检测概况：样本天数 / 离群方法 / 缺失天数 / 预警总条数 / 确认异常条数 / 特殊期拦截条数 / 行业基准 |
| `alerts` | array | 预警清单，每行含 日期 / 星期 / 指标 / 规则 / 级别 / 实际值 / 阈值基线 / 证据 / 判定 |
| `data_quality` | array | 数据质量问题：缺失日期、新店保护期、单日样本量不足，含处理方式 |

**级别**取值：`高`（当天处理）/ `中`（1~3 天复盘）/ `低`（只报值观察）/ `拦截`（不进异常清单）。

## 输出产物

| 文件 | 内容 |
|---|---|
| `out/异常预警清单.xlsx` | 5 个 sheet：预警清单（高风险行标红）/ 指标明细 / 星期对齐 / 数据质量 / 汇总 |
| `out/趋势图.png` | 营收与转化率双轴趋势图，确认异常点用红点标出 |
| `out/detect.json` | 机器可读结果，供工作流与下游技能读取 |

## 使用步骤

### 方式一：纯提示词（最快，任意平台）

1. 打开支持自定义提示词的 AI 工具（Coze / WorkBuddy / Dify / Claude / ChatGPT…）
2. 把 `prompt.txt` 的**全部内容**粘贴为系统提示词
3. 按「输入规格」提供门店日指标数据（JSON 或表格都行）
4. 得到按级别排序的异常预警清单与排查方向

### 方式二：带脚本（推荐，产出真实文件）

```bash
python3 <SKILL_DIR>/scripts/detect.py --input input.json --outdir out
python3 <SKILL_DIR>/scripts/detect.py --demo --outdir out      # 无输入也能看效果
```

Windows 下若 `python3` 不可用则用 `python`。脚本会用 `lib/assettools.py` 做统计与出图，
缺依赖时会打印修复命令（如 `python -m pip install pandas openpyxl matplotlib`）并以退出码 2 结束，**不静默失败**。

**分工**：脚本做**派生指标计算、四规则判定、星期对齐、离群检测、产物落盘**；
模型做**语境解释、排查方向撰写、与店主确认口径**。数值一律以脚本输出为准。

## 边界（不做的事）

- ❌ 不写日报/周报正文（交给 `daily-report-copy`），不做经营决策
- ❌ 数据缺失时不填默认值、不估算 —— 列清单让用户补
- ❌ 不用模型口算替代脚本的派生指标与判定
- ❌ 不跨缺失日期做环比（补零会制造假跌）
- ❌ 不把促销日、节假日、新店期的波动判成异常
- ❌ 不用单日订单 < 20 单的转化率/退款率下结论
- ❌ 不承诺"调整后可提升 X%"之类的效果

## Hard Rules

- **必须真实运行脚本**，禁止自己编造 xlsx / png / json 内容或声称"已生成"
- **所有数值以脚本输出为准**（`summary`、`alerts`、`data_quality` 均从 `detect.json` 读取）
- 派生指标（客单价 / 转化率 / 退款率）**由脚本计算**，不接受用户提供的版本
- 缺失数据时列出缺失清单让用户补，**不补零、不估算**
- 异常清单里**"拦截"项必须保留并写明拦截原因**，让用户知道你考虑过它
- 每条"确认异常"必须配 1 条可执行的排查方向，不写"建议关注"这类空话
- 输出需标注「AI 生成内容」，交付前须经门店负责人人工复核

## 调用示例

**输入**（`examples/input.json`，望京 SOHO 店 2026-09 月度数据，29 行）：

```json
{
  "store_name": "望京 SOHO 店",
  "category": "餐饮",
  "period": {"start": "2026-09-01", "end": "2026-09-30"},
  "opened_date": "2025-04-18",
  "promo_days": ["2026-09-18"],
  "holidays": ["2026-09-25"],
  "metrics": [
    {"date": "2026-09-01", "revenue": 8653, "orders": 138, "visitors": 4620,
     "refunds": 219, "last_year_revenue": 7514}
  ]
}
```

**输出**（脚本实跑，24 条预警：确认异常 18 / 只报值 4 / 特殊期拦截 2）：

| # | 日期 | 星期 | 指标 | 规则 | 级别 | 实际值 | 判定 |
|---|---|---|---|---|---|---|---|
| 1 | 2026-09-09 | 周三 | 营收连续趋势 | R3 连续趋势 | 高 | 连续 4 天下滑，累计 -23.1% | 确认异常 |
| 3 | 2026-09-20 | 周日 | 退款率 | R1 绝对阈值 | 高 | 7.90% | 确认异常 |
| 9 | 2026-09-08 | 周二 | 营收同比 | R4 季节性 | 中 | -25.0% | 确认异常 |
| 15 | 2026-09-22 | 周二 | 转化率离群 | R2 离群 | 中 | 1.45%（Z=-2.01） | 确认异常 |
| 19 | 2026-09-27 | 周日 | 转化率 | R1 绝对阈值 | 低 | 0.80% | 只报值不下结论（当日 15 单） |
| 23 | 2026-09-18 | 周五 | 营收离群 | R2 离群 | 拦截 | 15,643 元（Z=+2.84） | 特殊期，需人工判断（周年庆促销日） |
| 24 | 2026-09-25 | 周五 | 营收环比 | R1 绝对阈值 | 拦截 | -22.3% | 特殊期，需人工判断（中秋节假日） |

完整结果见 `examples/output.md` 与 `out/异常预警清单.xlsx`。
