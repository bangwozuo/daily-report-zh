# 使用示例

> 本文档中的输入输出均为**真实实跑结果**（`scripts/report_copy.py --input examples/input.json`，退出码 0），
> 派生指标由脚本公式重算，不是占位示例。完整产物见 `examples/output.md` 与 `out/`。

## 示例 1：下滑日 —— 周六掉量 + 2 个确认异常（主示例，脚本实跑）

**场景**：望京 SOHO 店 2026-09-12（周六）打烊后，店主需要一份 30 秒能读完的日报。
输入含当日指标、上周同星期对比，以及 `anomaly-detect` 脚本产出的 2 条确认异常。

**输入**（`examples/input.json` 摘要）：

```json
{
  "period": "2026-09-12", "store_name": "望京 SOHO 店", "category": "餐饮",
  "metrics": {"date": "2026-09-12", "weekday": "周六",
              "revenue": 6895, "orders": 124, "visitors": 5957, "refunds": 276},
  "compare": {"上周同星期（2026-09-05 周六）": {"revenue": 11276, "orders": 174, "visitors": 5762, "refunds": 278},
              "同星期均值（9 月全部周六）": {"revenue": 10474}},
  "special_days": [], "store_age_days": 512,
  "alerts": [
    {"指标": "营收", "级别": "高", "实际值": "¥6,895", "阈值/基线": "环比 ≤ -20%", "判定": "确认异常"},
    {"指标": "退款率", "级别": "中", "实际值": "4.00%", "阈值/基线": "健康线 < 3%", "判定": "确认异常"}
  ]
}
```

**输出**（Word 日报《经营日报.docx》五节 + Excel《日报数据摘要.xlsx》五 sheet）：

> **一句话结论**：今天掉了，营收 ¥6,895，比上周同星期少 38.9%，问题出在到店客流，不是订单质量。

| 指标 | 本期 | 对比 | 判定 |
|---|---|---|---|
| 营收 | ¥6,895 | 上周同星期（2026-09-05 周六）¥11,276，**-38.9%** | 超出 20% 波动带，需当天复盘 |
| 退款率 | 4.00% | 健康线 < 3% | 需关注 |
| 订单数 | 124 单 | 上周同星期 174 单，-28.7% | 与营收同向 |

异常点与排查方向（**异常必给排查方向，不写"建议关注"空话**）：

| 指标 | 级别 | 实际值 | 阈值/基线 | 排查方向 |
|---|---|---|---|---|
| 营收 | 高 | ¥6,895 | 环比 ≤ -20% | 按小时拆分营收定位掉量时段，先看外卖曝光与进店客流哪个先掉，再决定调流量还是调活动 |
| 退款率 | 中 | 4.00% | 健康线 < 3% | 逐单核对当日退款原因，按出餐慢 / 配送超时 / 质量问题分桶，占 60% 以上的桶先处理 |

明日建议（责任人 + 动作 + 范围，脚本按触发条件生成）：

1. 让店长明天逐单看近 3 天的退款原因，先确认集中在出餐慢还是配送，锁定主要桶再处理
2. 让店长复盘高峰时段（10:00—14:00）的外卖曝光与进店转化，先确认是流量没进来还是进来了没下单

**关键数挑选过程**（脚本按优先级取前 3）：营收（必选）→ 退款率 4.00% > 3%（入选）→
转化率 2.08% 健康（不入选）→ 客单价 -14.2% 带内（不入选）→ 兜底补订单数。**正好 3 个。**

## 示例 2：星期对齐 —— 同一份数据换个比法结论完全不同

**场景**：09-12 是周六，如果偷懒拿前一天（09-11 周五 ¥8,679）做对比：

| 比较口径 | 结果 | 能否采用 |
|---|---|---|
| vs 09-11 周五（前一日） | -20.6% | ❌ 跨星期比较，周末效应污染 |
| vs 09-05 上周六 | **-38.9%** | ✅ 采用（脚本自动选星期对齐口径） |
| vs 同星期均值 ¥10,474 | -34.2% | ✅ 采用 |

**结论差异**：看环比只有 -20.6%，像是"略有回落"；按星期对齐后是 **-38.9%**，属于必须当天复盘的
量级。脚本 `weekday_aligned()` 自动在 compare 中优先选择含星期几的口径，**不做跨星期比较**。

## 示例 3：平淡日 —— 不硬凑"异常"

**场景**：2026-09-30（周三）营收 ¥9,618，09-29（周二）¥9,236，波动 +4.1%；无 alerts。

**脚本输出处理**：波动 +4.1% 落在 ±10% 正常带内 → 判定列写「正常波动带内」；
无确认异常 → 异常清单显示「（本期无确认异常）」；
建议仅剩「今日各项在健康区间，维持现有排班与出餐节奏，无专项动作」。
**不因为"日报必须写点什么"就硬造异常。**

## 示例 4：小样本不下结论（脚本内建）

**场景**：雨天当日只有 15 单（< 20 单小样本线），退款率 12.72%、转化率 0.80%。

**脚本输出处理**：`small_sample=True` → 转化率与退款率的判定列自动改写为
「只报值不下结论（订单 < 20 单，小样本只报值）」，**不触发退款率/转化率的任何建议规则**；
行动建议落在可核实的事上。阈值判定逻辑在代码里写死，模型无法绕过。

## 示例 5：特殊期豁免（脚本内建）

**场景**：2026-09-18 周年庆促销（`special_days` 含该日期），营收 ¥15,643（偏离 +55.75%）。

**脚本输出处理**：`special=True` → 一句话结论改写为「为特殊期（促销/节假日），
偏离属活动带动，不按异常处理」，营收判定列为「活动带动（特殊期）」，
**不触发"营收下滑需复盘"类建议**——活动期的增量不可复制到平日。

## 示例 6：空话 → 可执行 的改写对照（建议生成规则内建于脚本）

| ❌ 空话（脚本不产出） | ✅ 脚本产出的建议（责任人 + 动作 + 范围） |
|---|---|
| 「建议关注退款率」 | 「让店长逐单看近 3 天的退款原因，先确认集中在出餐慢还是配送」 |
| 「提升转化率」 | 「让运营检查这两天投的泛流量广告，把预算挪到进店转化最高的渠道，先跑 3 天看转化」 |
| 「持续优化经营」 | 「让店长核对套餐与满减结构，检查高单价商品动销，本周内恢复客单价到 ±15% 带内」 |

## 示例 7：--demo 模式（无输入也能跑）

```bash
python scripts/report_copy.py --demo
```

内置与 `examples/input.json` 相同的样例数据（含 2 个确认异常），跑通即产出
`out/经营日报.docx` + `out/日报数据摘要.xlsx` + `out/report_copy.json`，用于快速验证环境与产物形态。
