# 日报文案生成

把一天的经营数据，写成**店主 30 秒能读完、且知道明天第一件事做什么**的一段话。

判断标准只有一条：**店主看完能不能说出"今天生意怎么样"和"明天第一件事做什么"？**
不能，就是没写好——数据表他自己也会看。

## 能力描述

按**固定结构**生成日报，不做数据罗列。结构即 Word 产物章节：**结论前置 → 核心指标表 → 异常点与排查方向 → 明日建议**。

数值计算、健康区间判定、关键数挑选由 `scripts/report_copy.py` 完成，**数值以脚本输出为准，不要自己算**；模型负责文案润色与归因的业务解释。

| 位次 | 内容 | 篇幅 |
|---|---|---|
| 1 | **一句话结论**：方向（涨/跌/稳）+ 幅度 + 归因 | ≤ 40 字 |
| 2 | **三个关键数**：只挑 3 个，每个都带参照物 | 3 行 |
| 3 | **一句提醒**（可选）：需要留意的风险，只写 1 条 | 1 句 |
| 4 | **一个行动建议**：责任人 + 动作 + 范围 | ≤ 60 字 |

关键数优先级：营收（必选）→ 退款率 > 3% → 转化率 < 2% → 客单价波动 > 15% → 兜底补订单数/访客数，
**取前 3 个，绝不超**。

派生指标全部由公式重算：客单价 = 营收 ÷ 订单、转化率 = 订单 ÷ 访客、退款率 = 退款额 ÷ 营收。

## 量化判定标准

| 指标 | 健康 | 需关注 | 需当天处理 |
|---|---|---|---|
| 转化率 | 2%~5% | 1.5%~2% | < 1.5% |
| 退款率 | < 3% | 3%~5% | > 5% |
| 客单价波动 | ±15% 以内 | 15%~25% | > 25% |

**波动定性**：±10% 内 = 正常波动，一句话带过；10%~20% = 提一句方向；> 20% = 必须点出并给排查方向。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `metrics` | object | ✅ | 指标数据：`revenue` / `orders` / `visitors` / `refunds`，可选 `date` / `weekday` / `last_year_revenue` / `rating` / `bad_reviews` |
| `period` | string | ⬜ | 报告覆盖的时间范围，如 `2026-09-12` 或 `2026-09-23 ~ 2026-09-29` |
| `compare` | object | ⬜ | 对比口径：上周同星期、同星期均值、去年同期等 |
| `special_days` | array | ⬜ | 已知特殊期（促销日 / 节假日），命中的日期不写"异常" |
| `store_age_days` | number | ⬜ | 门店开业天数，< 30 天时偏离写"新店常规波动" |
| `alerts` | array | ⬜ | 确认异常清单（推荐取自 `anomaly-detect` 脚本 detect.json），每条含 指标/级别/实际值/阈值基线/证据/判定；日报只引用已判定异常，不重复检测 |
| `store_name` | string | ⬜ | 门店名称，用于标题 |
| `category` | string | ⬜ | `餐饮` / `零售`，影响健康区间口径 |

**不要把客单价 / 转化率 / 退款率直接给出来当结论** —— 用公式重算并校准；有出入以重算为准。

| 字段 | 类型 | 说明 |
|------|------|------|
| `headline` | string | 一句话结论：方向 + 幅度 + 归因，≤ 40 字 |
| `metrics_summary` | array | 三个关键数：每行含 指标 / 本期 / 对比 / 判定 |
| `drivers` | array | 归因说明：为什么是这个结果（含星期对齐核对结论） |
| `suggestion` | array | 行动建议：责任人 + 动作 + 范围，每条 ≤ 60 字 |
| `reminder` | string | 一句提醒（可选）：需留意的风险，只写 1 条 |

**脚本产物**（`scripts/report_copy.py` 实跑产出）：

| 文件 | 内容 |
|---|---|
| `out/经营日报.docx` | 五节 Word：一句话结论 / 核心指标表 / 异常点与排查方向 / 明日建议 / 数据口径与人工确认 |
| `out/日报数据摘要.xlsx` | 核心指标（需关注标红）/ 全部指标 / 异常清单（高级别标红）/ 明日建议 / 汇总 |
| `out/report_copy.json` | 机器可读结果：headline / key_metrics / all_metrics / anomalies / suggestions |

## 使用步骤

### 方式一：带脚本（推荐，产出 Word + Excel）

```bash
python3 <SKILL_DIR>/scripts/report_copy.py --input input.json --outdir out
python3 <SKILL_DIR>/scripts/report_copy.py --demo        # 无输入也能跑出含 2 个异常点的样例日报
```

脚本负责数值计算、健康区间判定、关键数挑选与异常排查方向映射；模型按 prompt.txt 润色文案与补充归因解释。

### 方式二：直接使用（纯提示词）

1. 打开任意支持自定义提示词的 AI 工具
2. 复制 `prompt.txt` 的**全部内容**作为系统提示词
3. 按「输入规格」提供当日经营数据（有对比数据一并提供）
4. 得到符合「输出规格」的日报

### 方式三：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |
| **ChatGPT** | 新建 GPT → Instructions → 粘贴 `prompt.txt` |

### 方式四：接异常检测结果（推荐）

先跑 `anomaly-detect` 的脚本拿到 `detect.json`，把 `alerts` 中"确认异常"的条目连同当日指标
一起喂给本技能。日报只引用已判定的异常，**不重复做异常检测**。

## Hard Rules

- **结论先行**：第一句话就说清楚好坏，不写"首先我们来看"这类过渡语
- **只报 3 个数**：宁可少说，不能超；第 4 个数店主记不住
- **每个数字都要有参照物**：孤零零的营收没有意义，必须带对比（上周同星期 / 同星期均值 / 去年同期）
- **必须按星期几对齐**：周末效应会造成 30%~50% 的正常波动，**严禁**拿周日和周六比
- **单日订单 < 20 单**：转化率与退款率只报值，**不下结论**
- **数据缺失**：不补零、不估算、不用"约"字掩盖，显式写"缺 X 天数据"
- **特殊期豁免**：促销日 / 节假日 / 新店未满 30 天，写"活动带动"或"节假日常规波动"，不写"异常"
- **正文 ≤ 200 字**：超出就是没提炼
- 派生指标用公式重算，**不用对话口算替代**

## 边界（不做的事）

- ❌ 不做异常检测（交给 `anomaly-detect`），不重复判定阈值
- ❌ 不做数据接入与字段校验（交给 `store-data-sync`）
- ❌ 不编造数据、案例或效果承诺；缺数据时列清单让用户补
- ❌ 不写"建议关注""加强管理""持续优化"这类没有责任人和动作的空话
- ❌ 不罗列超过 3 个关键数
- ❌ 不预测未来营收数字，不给投资级经营建议
- ❌ 不涉及资金操作、不代替店主做经营决策

## 调用示例

**输入**（`examples/input.json`）：

```json
{
  "period": "2026-09-12",
  "store_name": "望京 SOHO 店",
  "category": "餐饮",
  "metrics": {
    "date": "2026-09-12", "weekday": "周六",
    "revenue": 6895, "orders": 124, "visitors": 5957,
    "refunds": 276, "last_year_revenue": 8120
  },
  "compare": {
    "上周同星期（2026-09-05 周六）": {"revenue": 11276, "orders": 174, "visitors": 5762, "refunds": 278},
    "同星期均值（9 月全部周六）": {"revenue": 10474}
  },
  "special_days": [],
  "store_age_days": 512,
  "alerts": [
    {"日期": "2026-09-12", "星期": "周六", "指标": "营收", "规则": "R2 硬阈值", "级别": "高",
     "实际值": "¥6,895", "阈值/基线": "环比 ≤ -20%", "证据": "上周六 ¥11,276，星期对齐偏离 -34.2%", "判定": "确认异常"},
    {"日期": "2026-09-12", "星期": "周六", "指标": "退款率", "规则": "R2 硬阈值", "级别": "中",
     "实际值": "4.00%", "阈值/基线": "健康线 < 3%", "证据": "退款 ¥276 ÷ 营收 ¥6,895 = 4.00%", "判定": "确认异常"}
  ],
  "notes": "09-12 无促销、非节假日，门店开业已 512 天"
}
```

**输出**（脚本 `report_copy.py --input examples/input.json` 实跑，退出码 0，2 条确认异常均附排查方向）：

> **今天掉了，营收 ¥6,895，比上周六少 38.9%，问题出在到店客流与客单价，不是订单质量。**

| 指标 | 本期 | 对比 | 判定 |
|---|---|---|---|
| 营收 | ¥6,895 | 上周六 ¥11,276，**-38.9%** | 超出 20% 波动带，需当天复盘 |
| 退款率 | 4.00% | 健康线 < 3% | 超线 1 个百分点，需关注 |
| 订单数 | 124 单 | 上周六 174 单，-28.7% | 与营收同向下滑 |

提醒：09-12 是周六，营收比同星期均值 ¥10,474 低 34.2%，**不是周末效应，是真掉量**。

建议：**让店长今天复盘 10:00—14:00 的外卖曝光与进店转化**，先确认是流量没进来还是进来了没下单。

完整输出与派生指标重算过程见 `examples/output.md`。
