# 门店数据对接

把门店的几路经营数据**合规地接进来**，并交付一份可核对的**数据接入体检清单**。

本技能**不连接任何外部系统**：它没有凭证、不登录后台、不调用平台 API、不爬数据。
它做的是「接线图 + 体检报告 + 操作清单」，真正的数据搬运由用户在平台侧完成。

## 能力描述

四类校验，逐类出结论：

1. **接入方式合规** —— 白名单：官方 API（授权范围内）、用户自行导出、手工录入；
   黑名单：爬取需登录的私密数据、模拟登录、协议机器人、接码平台 → 判定红线并剔除
2. **字段映射完整** —— 字段完整率 = 实到字段 ÷ 应到字段；< 80% 标黄、< 50% 视为该源不可用；
   每个缺失字段给出**降级路径**（如缺 `revenue` 用核销金额 × 客单价估算并标注"估算值"）
3. **到数覆盖率** —— 覆盖率 = 当日实到源数 ÷ 应到源数；连续 ≥ 2 天断供触发补数提醒；
   断供日**不补零**
4. **脱敏红线** —— 扫描手机号 / 身份证号 / 银行卡号 / 邮箱 / 详细地址 / 客户姓名，命中即从数据集删除该字段

## 只读接入 SOP（时间轴）

| 时间 | 步骤 | 动作 | 人工确认点 |
|---|---|---|---|
| 每日 21:30 | 收数 | 官方 API 拉取 / 用户导出文件导入 | 🔒 确认当日营业结束、数据已落定 |
| 每日 21:35 | 校验 | 跑字段完整率与到数覆盖率，红线源直接剔除 | 🔒 确认红线源替代方案 |
| 每日 21:40 | 脱敏 | 扫描五类个人信息，命中即删字段 | 🔒 确认无残留 |
| 每日 21:45 | 交付 | 产出 Excel + 2 张 PNG + sync.json | 🔒 确认后交日报流程 |
| 每周一 09:00 | 巡检 | 复核授权状态与 token 有效期，导出断供记录 | 🔒 确认续期责任人 |
| 每月 1 日 | 复盘 | 统计完整率与断供次数，更新最小字段集 | 🔒 确认字段集变更 |

## 降级路径（缺字段不停摆）

| 缺失字段 | 降级做法 |
|---|---|
| `revenue` | 用「团购核销金额 × 客单价」估算，**必须标注「估算值」** |
| `orders` | 客单价不可算，报告写「客单价缺失」，**不推算** |
| `visitors` | 转化率不可算，只报订单量与营收 |
| `refunds` | 从平台售后单 + 评价内容人工汇总，标注「人工汇总」 |
| `团购核销` | 开启平台核销回传；未开启前该指标留空 |
| 全部字段都拿不到 | 该源标记「不可用」并列出，**不臆造数据填充** |

## 授权与降级路径（连接器）

- **有官方 API**：直接调用，只取授权范围内字段
- **无 API 但有商家后台**：用户自行导出 CSV / Excel，人工导入
- **两者都无**：用公开榜单 / 行业报告估算（标注来源），**不做爬取**
- **授权到期**：`last_sync` 距今 > 24 小时且为官方 API → 标记「授权可能到期」，提醒责任人续期；
  未授权的源**一律不得采集**，且不得用缓存数据冒充当日数据

## 使用步骤

### 方式一：纯提示词（最快，任意平台）

1. 打开支持自定义提示词的 AI 工具（Coze / WorkBuddy / Dify / Claude / ChatGPT…）
2. 把 `prompt.txt` 的**全部内容**粘贴为系统提示词
3. 按「输入规格」提供数据源清单与字段现状
4. 得到接入体检报告与降级路径

### 方式二：带脚本（推荐，产出真实文件）

```bash
python3 <SKILL_DIR>/scripts/sync.py --input input.json --outdir out
python3 <SKILL_DIR>/scripts/sync.py --demo --outdir out      # 无输入也能看效果
```

Windows 下若 `python3` 不可用则用 `python`。脚本缺依赖时会打印修复命令
（如 `python -m pip install openpyxl matplotlib`）并以退出码 2 结束，**不静默失败**。

## 边界（不做的事）

- ❌ **不连接外部系统**：无凭证、不登录后台、不调用平台 API、不爬取
- ❌ 不采用或建议任何黑名单接入方式（爬取、模拟登录、协议机器人、接码）
- ❌ 不录入手机号 / 身份证号 / 银行卡号 / 邮箱 / 详细地址 / 客户姓名；不做"先存再脱敏"
- ❌ 缺字段时不编数据、不填默认值、不补零
- ❌ 不做经营分析结论（交给 `anomaly-detect` 与 `daily-report-copy`）
- ❌ 不做资金操作、不代做签约或授权决策

## Hard Rules

- **必须真实运行脚本**，禁止自己编造 xlsx / png / json 内容或声称"已生成"
- **数值以脚本输出为准**（字段完整率、覆盖率、脱敏命中均从 `sync.json` 读取）
- 红线数据源（爬取等）**必须在进入下游之前剔除**，并在清单里写明替代方案
- 脱敏命中项要**真的从数据集删除字段**，不是只打个标记
- 断供日**不得补零**，缺失就是缺失
- 每个缺失字段必须配 1 条降级路径，不写"建议补充数据"这类空话
- 输出需标注「AI 生成内容」，交付前须经门店负责人人工复核

## 调用示例

**输入**（`examples/input.json`，5 个数据源 + 30 天到数记录 + 4 条原始值抽样）：

```json
{
  "store_name": "望京 SOHO 店",
  "period": {"start": "2026-09-01", "end": "2026-09-30"},
  "sources": [
    {"source": "收银系统", "access": "官方API", "authorized": true,
     "owner": "店长 王敏", "last_sync": "2026-09-30T21:32:00",
     "expected_fields": ["date", "revenue", "orders", "visitors", "refunds"],
     "actual_fields": ["date", "revenue", "orders", "visitors", "refunds"]},
    {"source": "竞品门店客流", "access": "爬取", "authorized": false,
     "owner": "运营 李强", "last_sync": "2026-09-28T19:00:00",
     "expected_fields": ["date", "客流估算"], "actual_fields": ["date", "客流估算"]}
  ]
}
```

**输出**（脚本实跑）：

| 数据源 | 接入方式 | 授权状态 | 字段完整率% | 缺失字段 | 判定 |
|---|---|---|---|---|---|
| 收银系统 | 官方API | 已授权 | 100.0 | — | ✅ 正常 |
| 美团/点评商家后台 | 用户导出 | 已授权 | 75.0 | 团购核销 | 🟡 字段不全 |
| 抖音开放平台 | 官方API | 未授权 | 33.3 | 团购核销、视频播放 | 🟡 未授权 |
| 企业微信 | 官方API | 已授权 | 100.0 | — | ✅ 正常 |
| 竞品门店客流 | 爬取 | 未授权 | 100.0 | — | 🔴 红线：禁止接入 |

体检结论：数据源 5 个（正常 2，红线 1）｜断供 3 天（09-15、09-16、09-23）
｜脱敏红线 4 条｜合规源平均字段完整率 77.1%。

完整结果见 `examples/output.md` 与 `out/门店数据接入清单.xlsx`。
