# 使用示例

> 本文档中所有数值均来自 `scripts/sync.py` 的**实跑结果**，不是手写示例。
> 复现命令：`python scripts/sync.py --input examples/input.json --outdir out`

## 示例 1：五源接入全量体检

**场景**：望京 SOHO 店店长想知道"每天从收银、点评、抖音、企业微信取数，到底接全了没有、干不干净"。

**输入**（节选自 `examples/input.json`）：

```json
{
  "store_name": "望京 SOHO 店",
  "period": {"start": "2026-09-01", "end": "2026-09-30"},
  "sources": [
    {"source": "收银系统", "access": "官方API", "authorized": true,
     "owner": "店长 王敏", "last_sync": "2026-09-30T21:32:00",
     "expected_fields": ["date", "revenue", "orders", "visitors", "refunds"],
     "actual_fields": ["date", "revenue", "orders", "visitors", "refunds"]},
    {"source": "美团/点评商家后台", "access": "用户导出", "authorized": true,
     "owner": "店长 王敏", "last_sync": "2026-09-30T21:40:00",
     "expected_fields": ["date", "团购核销", "评价数", "评分"],
     "actual_fields": ["date", "评价数", "评分"]}
  ],
  "daily_arrival": [{"date": "2026-09-01", "arrived": 4, "expected": 4}],
  "raw_samples": [{"source": "企业微信", "field": "customer_phone", "value": "13800001111"}]
}
```

**实跑结果**：数据源 5 个（正常 2 / 未授权或字段不全 2 / 红线 1）｜断供 3 天｜脱敏红线 4 条｜
合规源平均字段完整率 77.1%。

| 数据源 | 接入方式 | 完整率% | 缺失字段 | 判定 |
|---|---|---|---|---|
| 收银系统 | 官方API | 100.0 | — | ✅ 正常 |
| 美团/点评商家后台 | 用户导出 | 75.0 | 团购核销 | 🟡 字段不全 |
| 抖音开放平台 | 官方API | 33.3 | 团购核销、视频播放 | 🟡 未授权 |
| 企业微信 | 官方API | 100.0 | — | ✅ 正常 |
| 竞品门店客流 | **爬取** | 100.0 | — | 🔴 **红线：禁止接入** |

## 示例 2：接入方式红线 —— 完整率 100% 也要剔除

**场景**：运营同事接了一路"竞品门店客流"，字段齐全、数据也拿到了，完整率 100%。
店长问："这个数据挺好的，为什么不用？"

**脚本判定**：`access = "爬取"` 命中黑名单 → 判定 **🔴 红线：禁止接入**，
处理动作 =「立即停止该数据源，改用官方 API 或用户导出」，
并且该源**被排除在完整性柱状图之外**（图中只有 4 个合规源）。

**理由**：爬取需登录的私密数据违反《数据安全法》与平台协议，还会带来账号封禁风险。
**字段再全也不能用同一把尺子衡量**——合规判定先于数据质量判定。

## 示例 3：字段缺失走降级路径，而不是停摆或编数

**场景**：美团/点评商家后台导出的表里没有「团购核销」列。

**脚本输出**：字段完整率 75%，缺失字段「团购核销」，降级路径 =「无核销数据则线上引流效果
不可评估，建议开启平台核销回传」；下游影响 =「无核销 → 线上引流效果不可评估」。

**对比**：如果缺的是 `revenue`，降级路径是「用核销金额 × 客单价估算，**并标注"估算值"**」；
如果缺的是 `orders`，则**不推算**，直接写「客单价缺失」。**不同字段的降级力度不同**。

## 示例 4：断供识别（不补零）

**场景**：9/15、9/16 门店停电，收银数据没导出；9/23 抖音授权到期未续期。

**脚本输出**：

| 日期 | 应到源数 | 实到源数 | 覆盖率% | 状态 |
|---|---|---|---|---|
| 2026-09-15 | 4 | 3 | 75.0 | 🟡 部分到数 |
| 2026-09-16 | 4 | 3 | 75.0 | 🟡 部分到数 |
| 2026-09-23 | 4 | 2 | 50.0 | 🟡 部分到数 |

**为什么重要**：覆盖率低于 100% 的日子，日报里必须标注"缺 X 源数据"；
覆盖率 < 50% 时当日数据不可用于趋势判断。**断供就是断供，不补零也不用前一天的数据顶替。**

## 示例 5：脱敏红线 —— 4 条个人信息挡住了入库

| 字段 | 类型 | 脱敏后示例 | 判定 |
|---|---|---|---|
| customer_phone | 手机号 | `13*******11` | 🔴 红线：禁止录入 |
| customer_id_card | 身份证号 | `11**************12` | 🔴 红线：禁止录入 |
| member_address | 详细地址 | `北京********************* 室` | 🔴 红线：禁止录入 |
| customer_name | 客户姓名/昵称 | `***` | 🔴 红线：禁止录入 |

**脚本只输出脱敏后示例**，原始值不写进任何产物文件。处理动作统一为
「从数据集中删除该字段，只保留代号/分层标签」。

## 示例 6：授权到期与人工确认点

**判定规则**：`last_sync` 距今 **> 24 小时**且该源为官方 API → 标记「授权可能到期」。
本例中抖音开放平台最近同步 2026-09-22T20:00，触发提醒，责任人"运营 李强"。
未授权的源**一律不得采集**，也不得用缓存数据冒充当日数据。

## 整改前后对照

| 项 | 改造前 | 改造后 |
|---|---|---|
| 能力范围 | 只能对单个系统"说明字段映射 + 操作清单"（输入 `system` / `task`） | 多源接入体检：接入方式合规、字段完整率、到数覆盖率、脱敏扫描四类校验 |
| 合规判定 | 仅一句"不能自动读写外部系统" | 白名单/黑名单逐条判定，爬取源判定红线并从图表中剔除 |
| 字段处理 | 罗列字段名 | 字段完整率量化 + **每个缺失字段配降级路径**（估算 / 不推算 / 人工汇总） |
| 断供处理 | 无 | 覆盖率 + 断供日期清单，**不补零** |
| 脱敏 | 无 | 六类个人信息正则扫描，命中即删字段，输出只给脱敏示例 |
| 调度 | 无 | 每日 21:30 只读接入 SOP（6 步，4 个人工确认点）+ 授权到期处理 |
| 产物 | 无文件 | `门店数据接入清单.xlsx`（5 sheet）+ 2 张 PNG + `sync.json` |
